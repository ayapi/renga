# mcp-peer receive-side debug log

Set `RENGA_DEBUG_CODEX_PEER_LOG` before starting renga to append receive-side mcp-peer records to the same JSONL trace used by the TUI Codex peer diagnostics. To investigate a nudge that appears to have produced an empty `check_messages` result, filter the trace to the affected `pane_id`, sort by `timestamp_unix_ms` and `record_sequence`, and compare the TUI nudge write/Enter records with nearby `peer_inbox_received`, `peer_inbox_ack_sent`, `peer_receipt_cache_hit`, and `check_messages` records. The `check_messages` entry shows the call form, cursor or acknowledgement metadata, queue lengths, and response metadata without recording the message body or acknowledgement token; timestamps from separate processes can coincide, so use the pane id and the per-process sequence together when reconstructing the order.
